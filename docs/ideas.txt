Features:

    Core Mechanics

        Wild Battle:
            encounter a pokemon, starting a timer
            time of battle is influenced by pokemon type
            once timer expires, catch a pokemon (auto)
            add the pokemon to the inventory
            receive battle rewards
            (optional) perfect catch mechanic, affecting outcome. 
            (optional) run from battle
            (optional) other users can join a battle and catch the same pokemon
            
            Properties:
                id (uuid): unique battle id
                user_ids (list[bigint]): users in the battle
                start_time (bigint): now() timestamp 
                duration (int): duration of battle in seconds
                end_time (bigint): calculated end time
                rewards (jsonb): a dict like {money: 123, item: item_name} to be given upon completion of the battle
                status (text): status like active, inactive, ran
                battle_pokemon_id (uuid): the id of the pokemon in the battle_pokemon table (essentially another reward)


        Shiny Hunting:
            users have predetermined rng using frames
            users can spend money to look ahead and see where their next shiny is
            users can spend money to reset their seed 
        
        Trainer Battle:
            users can battle trainers 
            come up with an interesting way to battle trainers that matches the core game loop but adds a twist
        
        Location:
            users can choose a region, else random
            users can travel to specific routes? restri
    Inventory Management:
        Filter list of pokemon
        Release pokemon

    Economy:
        Market:
        Lottery:
        Trade:
            user1 is who initiates trade using (.trade user_id) command
            a local_id is generated (1-999) for both users to confirm with, easily typable vs a uuid
            pokemon, money and items can be traded, all optionally but at least 1 must be sent from each user
            both users must use the confirm command (.confirm local_id)
            Commands:
                .trade user_id: initiates a trade
                .trade add pokemon|item|money pokemon_local_id|item_local_id|amount
                .trade remove pokemon|item|money pokemon_local_id|item_local_id|amount
                .confrim local_id

            users can only be in one trade at a time, application should query for any active trades


            Properties:
                id (uuid): unique id for the trade
                local_id (int): id used to confirm trade, 1-999
                user1 (bigint): id of user 1
                user2 (bigint): id of user 2
                user1_pokemon_id (uuid): optional id of user1 pokemon being traded
                user2_pokemon_id (uuid): optional id of user2 pokemon being traded
                user1_money (int) - optional money sent in trade from user 1
                user2_money (int) - optional money sent in trade from user 2
                user1_item (jsonb) - optional item sent in trade from user 1, uuid and quantity
                user2_item (jsonb) - optional item sent in trade from user 2, uuid and quantity
                active (boolean): is the trade active (not confirmed by users)
                

        Items:
            Properties:

                user_id (bigint): unique user id
                name (text): item name
                quantity (int): quantity of item
